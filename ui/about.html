Inside System One Search

Small questions.
A connected picture.

A repository already contains its explanation: names, comments, source lines and references. The harness finds those pieces and puts them in order.

The principle

Code computes.
TypeSafe judges.

Jev, TypeSafe’s decision model, answers small, typed questions: does this file belong to the subject? Which candidate best answers the question? Does this reference carry the work?

The surrounding code handles retrieval, thresholds, ranking, graph building and layout. There is no language model writing an explanation. Titles are identifiers, summaries are extracted comments, and arrows come from real references.

01

Read once.
Keep useful facts.

Tracked files become a tree. A content pass extracts declarations, imports, calls, comments and other language-specific facts. Compact signatures put distinctive facts first.

files → facts → signatures
02

Let code do
the broad search.

A lexical index scores paths, facts and source text. A reference graph connects files. These propose candidates before a single model judgment is needed.

lexical pool + reference graph
03

Ask one precise
question at a time.

For Find, TypeSafe shortlists candidates and verifies them against relevant source lines. For Map, it judges membership in a subject. If Find needs more evidence, the harness can walk the repository tree.

pool → shortlist → verify
04

Trace the subject.
Keep the evidence.

Explain gathers relevant files, expands through the reference graph, judges evidence blocks, and checks which references carry the subject’s work. Code assembles the chart and reading order.

gather → expand → evidence → edges → build

What an answer means

Inspectable.
Not infallible.

Every result links back to source. A judgment is a probability, not a proof. A flow shows the portion found within its search depth and caps; it does not establish that the entire behavior has been captured.

Static references cannot reveal every runtime relationship. Dynamic imports, dependency injection, client–server boundaries and language-specific wiring may leave gaps. The demo exposes the trace, omitted units, time and cost so you can assess the result.

Questions about public repositories are logged to improve the demo. Don’t include secrets.
